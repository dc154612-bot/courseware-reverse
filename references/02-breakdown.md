# 拆解模板：八个维度

每一项写两句话：**看到了什么**（事实）和**为什么这样设计**（推断，标【推断】）。看不清的标【未看清】。

| 维度 | 要回答的问题 |
| --- | --- |
| 1. 定位 | 哪个学段、学科、知识点？课堂投影用，还是学生自己操作？ |
| 2. 开场 | 第一屏用什么抓住人？一句话钩子、一个画面、一个问题？ |
| 3. 结构与导航 | 内容怎么分块？有几层导航？学生怎么知道自己在哪、还剩多少？ |
| 4. 核心交互 | 学生动手做的那一件事是什么？操作和知识是什么关系？ |
| 5. 讲解与节奏 | 文字讲解和画面怎么配合？一步讲多少？谁控制节奏（学生、老师、自动）？ |
| 6. 反馈 | 操作后系统给什么回应？做错时说了什么？ |
| 7. 视觉与氛围 | 配色、字体、材质、声音。哪些服务于学科情境，哪些只是装饰？ |
| 8. 技术形态 | 单文件还是网站？要不要联网？2D、3D 还是视频？手机能用吗？ |

## 按类型补充

八个维度之外，不同类型的作品还要额外看几点：

| 类型 | 额外要看的 |
| --- | --- |
| 多页网站 | 页面之间的关系：线性、分支，还是自由跳转？每页只讲一件事吗？ |
| H5（手机） | 竖屏排版、触控手势、一屏的信息量；能否在课堂投影上用 |
| PPT / PDF | 每页信息量；动画是讲解节奏还是装饰；触发器和跳转构成什么样的互动结构 |
| 希沃白板、小程序 | 哪些是平台功能（蒙层、克隆、班级数据），哪些是作者设计；换平台后还剩什么 |
| 教学游戏 | 见下表 |

教学游戏的拆解维度：

| 维度 | 要回答的问题 |
| --- | --- |
| 核心循环 | 玩家一轮里反复做的动作是什么？这个动作本身是不是在用知识？ |
| 关卡递进 | 难度怎么增加？是知识变难，还是只是变快、变多？ |
| 奖励 | 奖励给的是“答对”还是“理解”？去掉奖励还有人愿意玩吗？ |
| 失败 | 失败时告诉玩家错在哪了吗？还是只扣血、重来？ |
| 融合度 | 游戏玩法和知识是一回事（做对才能过关），还是答题和游戏两张皮（答完题才能玩一会儿）？ |

“两张皮”的游戏，学到的知识和玩法没有关系，去掉游戏外壳也不影响学习，脱壳测试会直接暴露这一点。

## 写法要点

- 区分“机制”和“皮肤”。机制是可以迁移到别的课的设计，例如“顶部一排字既是目录又能直达”；皮肤是这个作品特有的外观，例如“墨绿墙面加木梁”。要学的是机制。
- 找出原作的“记忆点”：老师第一眼说“做得好”的，通常就是这一处。把它说清楚，比把八项都写满更重要。
- 估算制作难度：老师自己用 AI 能不能做出来？哪些部分最难（3D、精确计算、大量素材）？

## 示例：八音文化长廊（抖音录屏，音乐课）

| 维度 | 看到了什么 → 为什么这样设计 |
| --- | --- |
| 定位 | 小学音乐，“八音”分类；课堂投影 → 【推断】老师带着全班“逛展” |
| 开场 | 直接进入 3D 长廊，尽头墙写“八音文化长廊” → 一进来就有空间感和终点 |
| 结构与导航 | 八类展区分成四组，左右成对排列；顶部“金石土革丝木匏竹”一排字可直达 → 导航本身就是知识的分类框架 |
| 核心交互 | 前后走动、转头，点击“+ 土类展区”看介绍 → 节奏由学生控制，有探索感 |
| 讲解与节奏 | 详细内容藏在按钮后面，墙面保持干净 → 避免一屏塞满文字 |
| 反馈 | 【未看到】录屏里没有测验或反馈环节 |
| 视觉与氛围 | 墨绿墙面、木梁、编钟实物图 → 贴合“传统乐器展馆”的情境 |
| 技术形态 | 可行走 3D 网页，有“保存案例 HTML”按钮 → 单文件、可离线 |

记忆点：可以“走进去”的 3D 展馆，加上直达分类的顶部导航。
