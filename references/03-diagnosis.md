# 闸门诊断与再创新

## 诊断表

完整标准见 teaching-design-gate 技能的四个参考文件。逐项判断“有 / 部分 / 没有”，并写出依据。

| 检查项 | 要回答的问题 |
| --- | --- |
| 教学对齐 | 能看出它要学生学会什么吗？有学习证据吗（学生做了什么能证明学会）？ |
| 交互匹配 | 核心操作是在练这个知识，还是只是在看、在点？ |
| 脱壳测试 | 去掉 3D、动画、积分和音效后，学生还在练这个知识吗？ |
| 错因反馈 | 做错时，有没有说清错在哪、下一步怎么做？ |
| 验收 | 学科内容是否准确？能否离线、投影、触屏使用？ |

常见结论：做得好看的作品，大多强在“交互匹配”的前半段（让人愿意操作），弱在“学习证据”和“错因反馈”。这正是再创新的空间。

也要核对原作的知识内容。如果发现错误，单独列出来，提醒老师不要照搬。

## 再创新：学 / 改 / 补

```
【学】直接迁移的机制（2～3 条）
  例：顶部分类导航可直达；讲解卡片藏在按钮后面，保持画面干净
【改】要换掉的部分
  内容：换成老师自己的知识点和题目
  外观：重新设计配色、字体和素材，不沿用原作
  技术：按老师的条件调整（如改成单文件离线）
【补】原作缺的闸门（1～2 条，挑最重要的）
  例：加一个“听音找展区”任务，选错时说明差在发声方式还是余音长短
```

“补”只挑一两条最重要的，优先补学习任务和错因反馈。一次补太多，作品会变复杂，老师也很难用 AI 做出来。

## 简版闸门（没有安装 teaching-design-gate 时使用）

老师确认要做的课后，按顺序完成：

1. 对齐卡：关键问题、理解目标、常见误区、学生操作、学习证据。学习证据不能是“看完了”或“通关了”。
2. 核心交互：学生操作什么 → 界面怎么变 → 学到什么；做脱壳测试，不通过就重新设计。优先“先预测再验证”。
3. 错因反馈：每个误区写出错误答案、背后的想法、反馈文字、下一步。
4. 生成要求：单个 HTML 文件、不依赖外网、只做一个核心交互、有重置按钮、投影大字号、完整输出代码。
5. 上课前人工核对：知识内容、答案、隐私。
