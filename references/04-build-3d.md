# 生成 3D 版本

目标：不管老师用哪个模型，都能做出一个能上课用的 3D 可视化网页，观感达到 WeduLab 这类精品的五到七成。做法是把画面质量放进固定的骨架里，模型只写学科内容。

## 一、先判断要不要 3D

适合 3D 的：知识本身有空间结构或空间过程。

- 地理：地形、水循环、大气环流、河流地貌、城市布局
- 生物：植株、细胞、器官结构、生态系统、种群
- 物理和化学：电路实物、光路、分子结构、实验装置
- 历史、语文：古建筑、场景复原

不适合 3D 的：公式推导、文字理解、数据统计、二维几何。这些按 teaching-design-gate 做 2D 页面，3D 只会增加负担。

教室电脑太旧、打不开 WebGL 时，骨架会显示提示，题目和记录照常能用。

## 二、精品 3D 好看在哪里

2026 年 11 月看 WeduLab 豌豆实验页加载了哪些资源：

- 没有 3D 模型文件，也没有图片。植株、温室、砖墙都是代码用几何体拼的
- 用了后期处理：环境光遮蔽（交界处有柔和暗部）、景深、轻微泛光、天空球
- 用了网络字体（宋体类衬线字）
- 页面代码加密下发，不去破解

所以“模型用得好”主要不是指美术建模，而是三件事：

1. 用简单几何体拼出有细节的东西，而且数量多、每个都有差异
2. 光影统一：一盏暖色主光、软阴影、天光、色调映射、雾
3. 镜头和版面：场景铺满屏幕，面板浮在上面，镜头跟着题目转

骨架已经做好第 2、3 件，还补了便宜的替代手法：移轴模糊代替景深，接触阴影代替环境光遮蔽，系统字体代替网络字体。模型只需要做好第 1 件。

## 三、场景卡（写代码前先填）

```
底座：沙盘、桌面、田地、实验台……（多数用 ground 沙盘，四边切开露出分层）
主体：3～6 个，每个写清用哪几个积木拼
  例：豌豆植株 = 茎 tube + 叶 ball 压扁 + 豆荚 ball 拉长 + 支架 cyl
成批的东西：什么、多少个、怎样有差异
会动的：只列表达知识的（水流、电流、生长）
要看的对象：每道题看哪个；各给一个视角和一个 tag
点选：点中哪些物体，弹出什么说明
```

主体的拼法比数量重要：一个用 4～6 个积木拼的主体，比十个光秃秃的立方体好看。

## 四、两条生成路线

### 路线 A：能写文件（Claude Code、WorkBuddy）

1. 复制 `assets/3d-template.html`，只改“学科内容开始 / 结束”之间的部分。结构照示例：SCENE → buildSubject → fresh → render → ACTIONS → onPick
2. 积木用法见 `assets/3d-提示词.md` 的积木清单
3. 运行 `python3 scripts/inline_three.py <文件>`，生成断网可用的单文件
4. 在浏览器里打开，逐个视角截图检查（见第六节）
5. 有 teaching-design-gate 时，再跑它的 `check_html.py`。它报的“联网请求”来自 three.js 自带的加载模块，页面没有调用，可以忽略

需要骨架没有的效果（例如精细的植株）时，在学科内容里直接用 THREE 写，不改骨架。

### 路线 B：只能对话（豆包、DeepSeek、Kimi 等）

1. 把 `assets/3d-提示词.md` 给老师，填好【】后发给 AI
2. 老师把回复的代码粘贴到 `assets/3d-拼装器.html`，生成、预览、下载
3. 拼装器会检查代码缺项和语法错误，并告诉老师该对 AI 说什么

弱一些的模型写长代码容易截断。所以只让它写学科内容，一般 150～300 行；画面质量靠骨架保底。

## 五、让画面好看的要点

骨架已经做好的（不要在学科内容里重复做）：

- 灯光：天光加一盏斜上方的暖色主光，投软阴影；ACES 色调映射
- 天空渐变和同色雾，雾跟镜头距离走，近看不发灰
- 移轴模糊：画面上下边缘轻微模糊，像微缩沙盘
- 镜头：画面中心放在两块面板之间；换题时平滑转过去；封面时缓慢摆动
- 标注用 HTML 文字跟着 3D 位置走，投影时清晰
- 窄屏改为上下排列；系统设置了“减少动态效果”时停掉动画

学科内容要做的：

- 用 ground 做底座，剖面分层写上名称
- 主体用多个积木拼，带上材质差异（深浅、粗糙、半透明）
- 成批的东西几十个起，大小、颜色、朝向都有差异
- 颜色低饱和、接近自然；强调色只给被问的对象
- 每道题一个视角，要看的对象不被别的东西挡住
- 答错时用 `.set('alt')` 把学生选的那一项也标出来

## 六、验收

- 封面、全景、每道题的视角各截一张图，和原作在同一尺寸下并排看：第一眼像不像在一个“世界”里？要看的对象清楚吗？
- 做错一次，看场景里有没有标出学生选的那一项
- 窄屏（820 宽左右）看一次；大屏按钮放大字号看一次
- 断网打开一次
- 性能：主体加成批物体总数控制在几千个积木以内；成批的东西一定用 scatter 或 trees，不要循环创建几百个独立物体

## 七、常见问题

| 现象 | 原因 | 改法 |
| --- | --- | --- |
| 场景很小、四周大片空白 | SCENE.size 写大了 | 按实际宽高改小 |
| 要看的东西被树挡住 | 撒点时没避开 | spots 的 avoid 里排除这块区域 |
| 画面发灰 | 雾太近 | 骨架已按镜头距离调；仍发灰就把 sky 换成 day |
| 物体浮在空中或陷进地里 | 没用 groundY | y 写成 groundY(x, z) |
| 箭头看不清 | 太细或颜色和背景接近 | r 调到 0.06～0.08；换和地面对比强的颜色 |
| 标注叠在一起 | 位置太近 | 标注放在物体上方，错开高度 |
| 预览时动画不动 | 浏览器窗口在后台，动画暂停 | 切到前台再看 |
| 红色提示条 | 学科内容代码出错 | 把提示原话发给 AI 修改 |
